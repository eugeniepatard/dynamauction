The problem

Every ad you win changes what the next one is worth

An advertiser bids again and again to show ads to the same user. Each ad shown can make the user convert, but it also tires them, so the next display is worth less.

Bidding well means planning: a test for reinforcement learning.

Abstract

What you win today changes what tomorrow's items are worth. DynamAuction is a simulator for this planning problem in repeated auctions, with a new class of MPC bidding policies as a baseline.

A buyer who repeatedly participates in auctions for related items often faces a dynamic value problem: what they win today changes what tomorrow's items are worth. Despite the empirical importance of such effects, especially in display advertising, the algorithmic literature on repeated auctions has largely focused on the learning problem, by treating each opportunity as a contextual bandit, while sidestepping the planning problem induced by the dependence of current value on past wins.

We introduce DynamAuction, a synthetic environment for single-buyer sequential bidding. The reward from each win depends on the buyer's history of previous wins, summarized through a carry-over state. The environment supports first- and second-price auctions, non-homogeneous Poisson arrivals, delayed feedback, saturation, and recency effects. We also introduce a new class of Model Predictive Control (MPC) algorithms. On our benchmark scenario, these MPC policies outperform off-the-shelf deep RL baselines (PPO, SAC, TD3) as well as a tuned shading baseline. We release DynamAuction to support RL research on repeated auctions.

The model

A kernel causal model of dynamic value

Three ingredients, each configurable in the simulator.

1

Carry-over context

Each past win leaves a trace on the user; the traces add up, in a commutative monoid, into one state that fades or grows with time.

\[ S_u(t) = \bigoplus_{i \,:\, t_i \le t} \gamma(x_i, t_i, t) \]
  • counter of wins
  • fatigue
  • time since last win
  • full history
2

Reward kernel

A won display pays off now and later: an immediate part and a delayed density, set by the context before the display.

\[ \mathcal K(A) = \kappa\, \delta_0(A) + \int_A \lambda(\tau)\, d\tau \]
3

A planning problem

The bidder sees only a summary \(\phi(S_u)\) of the context and never the end \(T\). It maximizes reward minus payments, so the right bid is the marginal value of a win, not the myopic value \(V_0\).

\[ \max_\pi\, \mathbb E\Bigl[\sum_i r_i - \sum_j p_j\Bigr] \]

A simplified re-implementation of the environment in your browser, for illustration: same formulas as the library (survival kernel, carry-over contexts, oracle value V₀, delayed conversions), short campaigns (mean length 10), at least 0.3 time units between two auctions so that they can be told apart, and a user drawn among those receptive to the ad. FiPla and Shading use the oracle value V₀, which RL agents do not see. The benchmark itself runs the Python package.
